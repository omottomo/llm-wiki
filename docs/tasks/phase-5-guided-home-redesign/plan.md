# Phase 5 — Guided Home Redesign (site-test)

## Context

- The published test site (`site-test/`, deploy target `omottomo-llm-wiki-test.pages.dev`) presents the wiki through Quartz defaults: the home page is plain markdown prose, the right sidebar shows a graph view, and there is no explorer or breadcrumb. First-time visitors don't know where to start.
- User priorities, in order: **직관성 (intuitive first contact), 단순함 (simplicity), 가독성 (readability)**.
- Decisions made with the user in this session:
  - **Guided home** ("여기서 시작" curation) over map-style or magazine-style homes.
  - **Keep Quartz** — heavy customization, no new stack.
  - **Keep the explorer** (currently `enabled: false` — must be re-enabled), **remove the graph view** (currently enabled), **enable breadcrumbs**.
  - Home implemented as a **card layout**: HTML blocks inside `content/index.md` styled by `custom.scss`. No TSX components (rejected: vendored-code debt, page counts are fine hand-written).
- **Scope: `site-test/` only.** The user framed the request around site-test. `site/` uses a full `content → ../wiki` symlink (its home is `wiki/index.md`), so porting this design there requires restructuring its content root — a separate later phase, after this design is visually validated.
- This is **code mode**: zero changes to `wiki/` prose. The home page `site-test/content/index.md` is a **site-owned regular file** (see `docs/rules/site-code.md` §2.4, "A test site is a second content root"), so rewriting it is code-mode work.

## Changes

### 1. Spike — verify raw HTML survives the build (do this first)

The card layout depends on `<div class="...">` blocks in markdown reaching the rendered HTML with classes intact. Before any real work: add a probe div to `content/index.md`, run `npx quartz build`, grep `public/index.html` for the class. If Quartz strips it, fall back to styling structural markdown (headings + lists + callouts) with CSS only — decide then, don't build both.

### 2. `site-test/quartz.config.yaml` — navigation plugins

- `graph` → `enabled: false`
- `explorer` → `enabled: true` (left sidebar, existing `position: left, priority: 50`)
- `breadcrumbs` → `enabled: true` (existing `condition: not-index` stays)
- Before writing any `options:` block for explorer, read `.quartz/plugins/explorer/dist/index.d.ts` — plugin options are not schema-validated and unknown keys are silently discarded (§2.4).
- After editing the `plugins:` block: `npx quartz plugin install --from-config` and **commit `quartz.lock.json`** (§2.2).

### 3. `site-test/content/index.md` — card home rewrite

Restructure the existing page. **Reuse the existing Korean copy** (it is already good — hero intro, 자막 주의 note, 지식 축적 흐름); the work is layout, not copywriting. New structure:

1. **Hero** — title + one-line pitch + the 자막 caveat condensed to one short line.
2. **"처음이면 — 순서대로" path cards (3)** — ① `overview` (도메인 개요) → ② `analysis/ai-coding-evolution` (진화 서사) → ③ `catalog` (위키 색인). Numbered cards, one line of description each.
3. **Category cards (4)** — 개념 18 · 인물 17 · 출처 27 · 분석 3, each linking to its folder listing page (`/concepts/`, `/entities/`, `/sources/`, `/analysis/` — generated by the already-enabled `folder-page` plugin). Counts are hand-written; accept the drift risk (noted below).
4. **지름길 — 분석 가이드 3편** — the three analysis guides as a compact link row.
5. **Footer section** — "지식은 이렇게 쌓입니다" condensed from the current 5-step list.

Card markup: plain `<div class="home-*">` wrappers around normal markdown links so wikilink resolution still applies (spike in §1 confirms the mechanism; if links inside raw HTML don't resolve, use plain relative hrefs — they are knowable and stable).

### 4. `site-test/quartz/styles/custom.scss` — card styles (additive only)

- `.home-*` grid: cards with the established hairline-border + 8px radius surface language (match the existing table/callout treatment from the 2026-07-19 redesign passes).
- Responsive: grid collapses to 1 column on mobile (`max-width` media query).
- **Theme tokens only** (`--secondary`, `--lightgray`, etc.) so light/dark both work without new colors.
- Do not touch article-page styles — readability polish was completed in earlier passes.

## Out of scope

- `site/` (production) — port after visual validation of site-test.
- `wiki/` prose — any edit there is content mode and forbidden in this phase.
- Auto-generated counts/recent-notes on the home — YAGNI; hand-written counts accepted.

## Known risks

- **Count drift**: the four category-card counts go stale with each ingest. Accepted by the user. A future ingest that adds a page should bump them, but nothing enforces it.
- **Raw-HTML rendering** is unverified until the §1 spike runs — the fallback (styled structural markdown) is defined above.
