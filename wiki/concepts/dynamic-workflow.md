# 다이나믹 워크플로우

**다이나믹 워크플로우(Dynamic Workflow)**는 Claude Code에 비교적 최근 추가된 기능으로, 사용자가 하나의 요청(싱글 프롬프트)을 던지면 메인 에이전트가 그 목적을 듣고 작업 방식을 리서치·계획한 뒤 **워크플로우(= 하네스)를 동적으로 생성**하는 방식이다 (→ [[sources/youtube-9fx2_1aTzq8]]). 정적인 하네스를 사람이 미리 짜 두는 대신, 요청마다 그에 맞는 하네스가 그 자리에서 만들어진다는 점이 핵심이다 (→ [[sources/youtube-9fx2_1aTzq8]]). 이 점에서 [[concepts/harness-engineering]]의 "동적 하네스 생성" 흐름과 직결되며, [[concepts/loop-engineering]]에서도 "어차피 울트라 코드를 쓰면 다이나믹하게 하네스가 생겨난다"고 언급된다 (→ [[sources/youtube-z-3BRkxQ5GM]]).

## 대표 두 기능: 딥리서치와 울트라 코드

다이나믹 워크플로우에는 대표적으로 **딥리서치(Deep Research)**와 **울트라 코드(Ultra Code)** 두 가지가 있다 (→ [[sources/youtube-9fx2_1aTzq8]]).

- **딥리서치**: 리서치(조사) 목적. Claude Code에 **기본 내장된** 워크플로우로, `딥 리서치`(또는 `deep research`) 명령으로 실행한다 (→ [[sources/youtube-fInMcawbKng]]). 조사 → 검증 → 추가 조사 여부 확인의 무한루프를 돌다가 끝나면 최종 리포트를 낸다 (→ [[sources/youtube-9fx2_1aTzq8]]).
- **울트라 코드**: 코드 생성 목적. 큰 작업을 던지면 병렬로 작업을 만들어 내고, 리뷰·검증 후 수정할 것이 있으면 다시 계획해 무한루프를 돌린 뒤 결과를 낸다 (→ [[sources/youtube-9fx2_1aTzq8]]).

## 실행 방법

워크플로우를 트리거하는 방법은 세 가지다 (→ [[sources/youtube-fInMcawbKng]]):

1. 프롬프트에 `울트라 코드`(ultra code) 키워드를 넣기 — 이번 턴이 다이나믹 워크플로우로 요청되었다고 표시된다.
2. "워크플로우로 ~작업을 진행해 줘"처럼 자연어로 요청하기.
3. 저장된 슬래시 명령어로 호출하기.

에포트(effort) 레벨은 `로우 / 미디움 / 하이 / X하이(xhigh) / 맥스`에 더해 **울트라 코드** 레벨까지 둘 수 있으나, 발표자는 기본 모드를 렉스(또는 X하이)로 두고 필요할 때만 `울트라 코드` 키워드를 입력하는 방식을 권장한다 (→ [[sources/youtube-fInMcawbKng]]).

## 페이즈(Phase) 분할과 병렬 에이전트

다이나믹 워크플로우의 본질은 **작업을 페이즈로 나누는 것**이다. 메인 에이전트가 각 페이즈의 정확한 목표·결과물을 정의하고, 페이즈마다 그에 맞는 하네스가 설정되도록 만든다 (→ [[sources/youtube-9fx2_1aTzq8]]). 딥리서치는 보통 스코프 → 서치 → 패치 → 검증 → 종합(리포트)의 단계로 진행되며, 각 페이즈 안에서 **다수의 서브 에이전트가 병렬**로 실행된다 (→ [[sources/youtube-fInMcawbKng]]).

- 실제 딥리서치 데모에서 서치 6개, 패치 28개, 검증 75개의 서브 에이전트가 병렬로 동작했고, 마지막 종합(리포트 작성)은 컨텍스트를 위해 단독으로 수행됐다 (→ [[sources/youtube-fInMcawbKng]], [[sources/youtube-9fx2_1aTzq8]]).
- 엔트로픽 공식 문서 기준, 워크플로우는 **동시 최대 16개**, 한 실행에 **누적 최대 1,000개**까지 서브 에이전트를 띄울 수 있다 (→ [[sources/youtube-fInMcawbKng]]).
- 울트라 코드는 컨텍스트가 더 중요하기 때문에 딥리서치보다 **적은** 수의 에이전트(예: 파운데이션 4개 → 빌드 14개 → 통합 2개 → 리뷰 3개)를 쓰지만, 각 에이전트가 더 오래 실행되므로 토큰 사용량은 오히려 더 많을 수 있다 (→ [[sources/youtube-9fx2_1aTzq8]]).

## 내부 구현: JS 스크립트 기반

다이나믹 워크플로우는 내부적으로 **자바스크립트(JS) 스크립트 기반**으로 동작한다 (→ [[sources/youtube-fInMcawbKng]]). Claude Code가 작업에 맞는 JS 스크립트를 짜서 백그라운드에서 실행하고, 기존 세션은 그동안 다른 작업을 계속할 수 있다. `워크플로우` 명령으로 진행 상황을 볼 수 있다 (→ [[sources/youtube-fInMcawbKng]]).

다른 병렬 기법과의 차이는 **"플랜(계획 문서)을 누가 들고 있느냐"**다 (→ [[sources/youtube-fInMcawbKng]]):
- [[concepts/subagents-agent-teams|서브에이전트]]는 각 에이전트의 턴 단위로, [[concepts/skills|스킬]]은 현재 메인 세션에서, 에이전트 팀은 팀 리드가 중앙 관리한다.
- 워크플로우는 **JS 스크립트 단에서** 플랜을 관리하기 때문에 수십~수백 개 규모의 에이전트 실행이 가능하다 (→ [[sources/youtube-fInMcawbKng]]).

워크플로우는 키보드 `S` 키로 저장하면 `.claude/워크플로우`(claude workflows) 폴더에 `.js` 파일로 보존되어 재사용할 수 있다 (→ [[sources/youtube-fInMcawbKng]]).

## 골(Goal)과의 관계

`골(Goal)`은 다이나믹 워크플로우와 같은 흐름에 있으나 **워크플로우 안에서 생성되지는 않으며**, 목표 지향성이 가장 높은 기법이다. 턴 제한이 없어 몇 시간~며칠을 돌며 정해진 목표가 달성될 때까지 실행된다 (→ [[sources/youtube-9fx2_1aTzq8]]). 골은 손으로 정의하기 어렵기 때문에 **메타프롬프팅**("이 작업을 할 골 프롬프트를 만들어 줘")이 필수다 (→ [[sources/youtube-9fx2_1aTzq8]]). 일반적인 작업은 빠른 완료에 초점을 둔 울트라 코드를, 검증이 정말 까다롭고 완벽해야 하는 작업은 골을 쓰라고 권장한다 (→ [[sources/youtube-9fx2_1aTzq8]]).

## 활용: 하네스 다이어트

다이나믹 워크플로우는 [[concepts/harness-engineering]]의 **"하네스 다이어트"**(낡은 하네스 제거)에 특히 유용하다. 모델 성능이 좋아지면 과거에 만든 하네스가 오히려 방해가 되거나 제품 내장 기능과 중복될 수 있는데, 이를 점검하는 데 적합하다 (→ [[sources/youtube-fInMcawbKng]]). 발표자는 두 개의 커스텀 워크플로우를 만들어 시연했다 (→ [[sources/youtube-fInMcawbKng]]):

1. **하네스 레거시 스캔**: 읽기 전용 감사 워크플로우. 인벤토리 → 애널라이즈(스킬·세이프티 퍼미션·프로덕트 오버랩 검증, 서브 에이전트 13개) → 플랜(리펙터 플래너) → 적대적 리뷰의 4단계로, 낡은 규칙·중복 지식·과도한 전역 컨텍스트·너무 넓은 스킬·불필요한 훅/MCP·제품 기본 기능과 중복되는 설정을 찾는다. 16개 에이전트로 109개 항목을 발견, 약 160만 토큰을 쓰며 17분간 실행됐다.
2. **하네스 다이어트**: 스캔 리포트를 바탕으로 스플릿 → 리파인 단계로 실제 최적화를 적용. 결과적으로 SKILL.md 본문이 약 2,600줄 → 1,800줄(약 760줄 절감), 활성 스킬 29개 → 28개로 줄었다.

발표자는 두 워크플로우를 한 달에 한두 번 돌려 하네스를 주기적으로 갱신할 것을 권장한다 (→ [[sources/youtube-fInMcawbKng]]).
