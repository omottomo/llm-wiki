# 가상화란 무엇인가 (AWS)

## 한 줄 요약

AWS의 입문용 개념 해설 페이지다. [[concepts/virtualization|가상화]]를 "서버·스토리지·네트워크 등 물리 장비의 가상 표현을 만드는 기술"로 정의하고, [[concepts/hypervisor|하이퍼바이저]] 두 타입과 가상화의 여섯 갈래를 훑는다.

## 핵심 내용

- **정의.** 가상 소프트웨어가 물리 하드웨어의 기능을 흉내 내어, 물리 머신 한 대 위에서 여러 가상 머신을 동시에 돌린다. 기업은 이것으로 하드웨어 투자 대비 수익을 끌어올린다.
- **동기 예시.** 이메일·고객용 앱·사내 앱은 요구 사항이 서로 다르다. 물리 서버 3대를 따로 사면 유지비는 100% 내면서 용량은 일부만 쓰게 된다. 가상화는 서버 한 대 위 VM 3대로 이를 대체한다.
- **이점 3가지** — 효율적 자원 사용(서버 풀에서 빌려 쓰고 반납), 자동화된 IT 관리(VM 템플릿으로 반복 배포), 빠른 재해 복구.
- **하이퍼바이저 두 타입.** 타입 1은 OS 대신 하드웨어에 직접 설치하는 베어메탈형이고, 타입 2는 기존 OS 위에 앱처럼 설치하는 호스티드형이다.
- **가상화 여섯 갈래** — 서버·스토리지·네트워크·데이터·애플리케이션·데스크톱. 네트워크는 다시 SDN과 NFV로, 데스크톱은 VDI와 로컬 방식으로 갈린다.
- **클라우드와의 관계.** 가상화가 클라우드 컴퓨팅을 가능하게 만든다. 사업자가 데이터센터를 갖추고 그 위에 가상 환경을 만들어 API로 열어 주면 그것이 클라우드다.
- **컨테이너와의 관계.** 컨테이너화를 애플리케이션 가상화의 한 종류로 규정한다. 서버 가상화가 두 지점을 잇는 도로를 놓는 일이라면 컨테이너화는 어디로든 날아가는 헬리콥터를 만드는 일이라는 비유를 쓴다.

## 주요 주장 / 데이터

- **"KVM은 타입 1 하이퍼바이저를 사용해 리눅스 운영체제 위에서 여러 VM을 호스팅한다."** 타입 구분을 단정하는 문장이다. 다른 자료와 충돌하므로 아래 연결 절에서 따로 다룬다.
- 타입 1은 "일부 운영체제 기능을 가지며 물리 자원과 직접 상호작용하기 때문에 매우 효율적"이라고 설명한다.
- 재해 복구 비교: 물리 서버를 교체·수리하려면 수 시간에서 수 일이 걸리지만, 가상 환경에서는 수 분이면 끝난다.
- 네트워크 가상화 두 방식 — SDN은 라우팅 관리를 물리 환경의 데이터 라우팅에서 떼어내 제어하고, NFV는 방화벽·로드밸런서·트래픽 분석기 기능을 묶어 성능을 올린다.
- 애플리케이션 가상화 세 방식 — 애플리케이션 스트리밍, 서버 기반, 로컬 방식.

## 기존 위키와의 연결

- 강화: [[concepts/virtualization|가상화]]의 종류·이점 서술. 여섯 갈래 분류는 [[sources/ibm-what-is-virtualization|#39 IBM 가상화 개요]]·[[sources/oracle-virtualization-explained|#36 오라클 가상화 해설]]과 대체로 겹쳐, 벤더가 달라도 같은 지도를 그린다는 점을 확인해 준다.
- 모순: [[entities/kvm|KVM]]의 하이퍼바이저 타입. 이 자료는 "타입 1"이라고 못 박지만 [[sources/redhat-what-is-kvm|#37 레드햇 KVM]]은 "리눅스가 하이퍼바이저로 동작한다"고만 쓰고 타입을 말하지 않는다. [[sources/wikipedia-virtualization-foundations|#40 위키백과 가상화 기초]]는 아예 "두 타입의 구분이 늘 명확하지는 않다"며 KVM을 그 사례로 든다. 양쪽을 모두 [[entities/kvm|KVM]]에 보존하고 모순으로 표시했다.
- 신규: [[concepts/virtualization|가상화]]·[[concepts/hypervisor|하이퍼바이저]] 개념 페이지가 이 묶음으로 생겼다.

- 수집된 본문 가운데 "What is virtualization?" 제목의 한 절이 "KVM을 제대로 이해하려면 먼저…"로 시작한다. AWS의 KVM 해설 문단이 추출 과정에서 섞여 들어온 것으로 보이며, 문제의 "KVM은 타입 1" 문장도 이 블록 안에 있다. 인용할 때 이 점을 함께 밝힌다.
