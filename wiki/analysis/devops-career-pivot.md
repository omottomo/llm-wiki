# 분석 — 3년차 DevOps '물경력' 이직 전략

> **질문**: DevOps 3년차인데 근무지 제약으로 제한된 기술만 써서, 이직하려는 회사의 요구·우대 기술과 갭이 크다. "물경력" 같은데 어떻게 이직을 준비할까?
>
> **근거 구성**: 프레임은 위키 [[concepts/career-pivot-strategy]]([[sources/youtube-SsHGSf_nzrI]])·[[concepts/developer-job-strategy]]([[sources/youtube-Vq9UU92R4wY]])에서 가져왔고, **DevOps 직군 특화 디테일(요구 스택·랩 구성·수치)은 2026-06 웹 리서치 + 다중 에이전트 적대적 검증을 통과한 항목만** 담았다(위키에 흡수된 원본 자료가 아니므로 `(웹, 2026-06 검증)`으로 표기). 검증에서 기각된 흔한 오조언은 맨 아래 "검증으로 걸러낸 것"에 남긴다.

## 1. 핵심 진단: 이건 "물경력"이 아니라 "좁은 경력"이다

위키의 기본 태도가 그대로 적용된다 — **지금까지의 경력을 부정하지 말고, 가고 싶은 방향과의 갭을 메우는 '증거'를 따로 만들어** "실무 경험 + 목표 방향 준비"를 둘 다 보여주는 것 (→ [[concepts/career-pivot-strategy]]). DevOps에서 변별은 **스택 개수(넓이)가 아니라 깊이**다. 좁게 썼더라도 "경험한 것만큼은 커널·근본까지 이해"로 프레이밍하는 편이 도구 20개 나열보다 강하다 (웹, 2026-06 검증).

## 2. 요구 스택 갭 지도 (3년차가 자주 비는 '우대' 영역)

DevOps 공고의 **요구사항(=입장권)**과 **우대사항(=변별)**을 분리해야 한다 (웹, 2026-06 검증).

- **입장권(baseline, 변별력 없음)**: 클라우드(AWS/GCP/NCP) · CI/CD · IaC(Terraform/Ansible) · Docker/K8s · Linux · Python/Bash. 3년차면 갖췄다고 **가정**된다.
- **우대(3년차가 미사용일 가능성이 큰 갭 — 여기서 승부)**:
  1. **GitOps + Progressive Delivery** — ArgoCD '배포'를 넘어 **Argo Rollouts(카나리/블루그린)**, SSOT/IaC로 클러스터 상태를 코드로. (2026 글로벌 디폴트, "Git에 없으면 존재하지 않는다")
  2. **OpenTelemetry 기반 통합 관측성·분산 트레이싱** — Prometheus 메트릭만 다룬 사람이 trace·instrumentation이 비는 경우가 많음. (2026.5 CNCF 졸업=사실상 표준)
  3. **정책/보안 as-code(DevSecOps)** — Kyverno·OPA Gatekeeper, Vault. RBAC까지는 해봐도 정책을 운영 적용한 3년차는 드묾.
  4. **서비스 메시 + eBPF** — Istio/Cilium/Hubble (시니어·플랫폼 공고 우대).
  5. **플랫폼 엔지니어링/IDP** — Backstage 골든패스, DORA 지표 계측. 운영만 한 사람에겐 통째로 빈 영역.
  6. **AI 활용 역량(AIOps/AI 코딩)** — 우대가 아니라 사실상 필수로 격상(글로벌 신규 DevOps JD의 다수가 AI 툴링 요구).

> **0순위 행동**: 막연히 "GitOps가 1순위"라고 단정하지 말고, **실제 지원 타깃 공고들의 우대사항을 수집해 본인 갭이 무엇인지부터 확정**하라(GitOps? 관측성? 클라우드?). 그다음 우선순위를 정한다 (웹, 2026-06 검증).

## 3. 위키 3대 방법의 DevOps 번역

| 위키 방법 ([[concepts/career-pivot-strategy]]) | DevOps 번역 |
|---|---|
| ① 실무 안에서 **AI 활용 경험** 만들기 | **AIOps / AI 코딩 에이전트**로 운영 자동화 (3-7절) |
| ② 목표 스택으로 **개인 서비스 배포·운영** | **재현 가능한 홈랩 + GitOps + 클라우드 실배포** (4절) |
| ③ **부하 테스트로 트래픽 경험** | **관측성·SLO·자동 롤백·부하 주입**으로 확장 (4절) |

위키의 "토이 프로젝트가 아니라 요청→저장→응답→**장애 대응**까지 전체 구조 증명"이 DevOps에선 "**IaC로 재현 가능한 플랫폼 + 의도적 장애 주입 + 자동 복구**"로 구체화된다.

## 4. 4주 차별화 랩 로드맵 (주말 단위, GitHub 공개 = '증거물 모드')

진단된 갭 우선순위에 맞춰 **1개를 끝까지** 한다. 토이가 아니라 운영 구조를 증명하는 게 목적 (웹, 2026-06 검증).

- **1주차 — 재현 가능한 홈랩 코어**: x86 미니PC(N100급) 2대 또는 라파5에 **k3s**(control-plane 1 + worker 1). 노드 프로비저닝은 Ansible/cloud-init, 설치는 스크립트로 코드화 → `make`/`ansible-playbook`으로 누구나 동일 클러스터 재현. README엔 친 명령 나열이 아니라 **아키텍처 다이어그램·전제·트러블슈팅**(라파면 `cgroup_memory` 함정, x86이면 swap off).
- **2주차 — GitOps 선언화**: **ArgoCD** 설치 후 워크로드를 Helm + ArgoCD Application으로. `kubectl apply` 수동 배포 금지(Git=단일 진실 원천). 보너스: **Argo Rollouts 카나리 1건 + AnalysisTemplate**으로 Prometheus 에러율·p95 질의 → **SLO 위반 시 자동 abort/rollback**. 의도적 실패 버전 + `k6`/`hey` 부하로 "자동 롤백이 실제 트리거되는" 장면을 대시보드/로그로 캡처.
- **3주차 — 관측성 1프로젝트**: `kube-prometheus-stack`을 ArgoCD로 배포(**CRD 262KB 한도 → `syncOptions: ServerSideApply=true`로 해결**한 경험이 면접 스토리). Grafana 대시보드를 `grafana_dashboard` 라벨 ConfigMap으로 Git 저장 → 사이드카 자동 임포트.
- **4주차 — 클라우드 실배포 1건**: AWS 프리티어로 Terraform end-to-end. **state는 S3 + `use_lockfile=true`(Terraform 1.10+, DynamoDB 불필요 — 구식)**. 핵심 업그레이드 = **GitHub Actions ↔ AWS OIDC 페더레이션(키리스)**. PR에 `terraform plan` 코멘트 → merge 시 apply, `tflint`/`checkov` 추가. **첫날 AWS Budgets $5~10 알림** 설정, 데모 후 `terraform destroy` + 잔여 리소스(EIP/스냅샷/백엔드 S3 버킷은 destroy로 안 지워짐) 수동 점검.

> 선택형 심화(공고에 맞춰 택1): **Kyverno/Gatekeeper 정책 리포**(latest 태그 금지·필수 라벨 + **단위테스트 + CI 통합 + 예외 승인 흐름** — '설치만'은 샘플 복붙과 구분 안 됨), **Cilium+Hubble eBPF 랩**(L7 가시성 명시 활성화 + 내장 mTLS), **Backstage 골든패스 1개**(부트스트랩 30분→3분 end-to-end 스토리).

## 5. 재직 중 자산 정량화 (가장 강력한 카드)

새 랩보다 **현재/직전 회사의 실제 성과**가 더 강하다. 본인 기여 범위(**I vs we**) 안에서 (웹, 2026-06 검증):

- **DORA 지표**: 솔로 사이드 파이프라인엔 억지 적용 금지(인시던트 없어 변경실패율·복구시간 무의미). **배포빈도·리드타임**만 git/CI 메타데이터로 산출. 네 번째 지표는 'MTTR'이 아니라 DORA 공식명 **'실패 배포 복구시간'**으로 표기.
- **신뢰성**: SLO·온콜 부담·알람 노이즈. **노이즈 감소는 반드시 '미탐 0·MTTD/MTTR 유지'와 짝지어** 제시(안 그러면 "그냥 뮤트한 것 아니냐"에 무너짐).
- **비용(FinOps)**: 본인 실측(Cost Explorer/Kubecost 전·후)으로. 업계 통상 20~40%를 그럴듯하게 베끼지 말 것 → "어떻게 측정했나"에 무너진다.
- **장애대응 STAR 2~3건**: S/T 짧게, **A/R(행동·결과)에 밀도**. 단 "재발률 0건"은 **기간을 박아야**("근본 수정 배포 후 N개월 동일 원인 재발 0건") 신뢰받는다.

## 6. 이력서·면접 재구성 (XYZ + 정직성)

- **XYZ 공식**: '액션동사 + 구체 기술 + 측정 결과'. 약→강 예: `'AWS 인프라 담당'` → `'AWS 인프라(EC2 120/RDS 15/ECS 8) 3개 환경 99.9% 가용성 관리'`; `'CI/CD 관리'` → `'Jenkins 테스트 병렬화로 빌드 45분→12분, 40+ 개발자 배포 3배 가속'` ([[concepts/ai-resume-writing]]의 "숫자로 증명"의 DevOps판).
- **정직한 PoC 표기**: 랩 결과는 `'운영'`이 아니라 `'개인 PoC로 구성·검증'`. **'랩 1회 ≠ 운영 경험'을 먼저 인정**하고 한계(소규모·장애/스케일/업그레이드 미경험)를 말하면 오히려 신뢰도가 오른다.
- **모든 항목을 강제 수치화하지 말 것**: 임팩트 큰 3~5개만 XYZ로, 나머지는 간결히(전부 수치화하면 padding으로 읽힘).
- **이직 사유**: 현 직장 비방 대신 성장 프레임. 단 "성장하고 싶다" 류 공허한 상투구는 경력 면접관이 가장 쉽게 간파 — **기술 포지셔닝**("운영자에서 플랫폼/신뢰성을 코드로 만드는 엔지니어로")으로 구체화.
- **답변 구조**: 개념 → 실무 적용 → 트레이드오프 → 숫자 마무리.

## 7. AI 활용 경험 (우대→필수, 위키 ①의 DevOps판)

가장 검증된 한 건만 골라 **측정 가능한 임팩트 + 출처(사내/샌드박스) 명시** (웹, 2026-06 검증):

- **AIOps 노이즈 감소**(권장): OSS로도 가능 — Prometheus+Alertmanager(grouping/inhibition), **OTel Collector로 라벨/의존성 정규화**(ROI 본체는 AI가 아니라 **입력 데이터 품질**), Grafana burn-rate. 베이스라인 2~4주 '전' 수치 → 정규화 → 규칙 적용 → '후' 측정.
- **AI 코딩 에이전트**: Copilot/Cursor/Claude Code로 Terraform·매니페스트·운영 스크립트 작성/리뷰. 작성 시간·문법오류·PR 리뷰 사이클 단축을 본인 실측으로.
- **정직성 단서**: "벤더 이상탐지 토글을 켜 알람 40%↓" 식은 게이밍 의심 → **데이터 엔지니어링(의존성 맵·라벨 정규화)을 헤드라인**으로.
- 포지셔닝: AI는 **'보조 전문성'**, 주 스파이크는 K8s+클라우드보안 또는 SRE+관측성. (NDA·회사 데이터 반출 금지, 수치만 일반화)

## 8. 자격증·우선순위

자격증은 **'서류 통과용 문 열기'**로만 기대하고 항상 포트폴리오와 짝지어라. 3개 동시 추진은 재직자 기준 6~12개월이니, **이직이 급하면 CKA(관리자, ≠CKAD) 또는 인지도 AWS SAA 1개 + 강한 포트폴리오로 먼저 지원**하고 나머지는 병행 (웹, 2026-06 검증).

## 9. 검증으로 걸러낸 것 (흔하지만 위험한 오조언)

다중 에이전트 적대적 검증에서 **기각**된 항목 — 따라 하면 면접에서 역효과 (웹, 2026-06 검증):

- ✗ **'리소스 개수 = 깊이'** (`EC2 120대` 자체를 역량 신호로): 허영 지표. 자동화 없이 수동 관리하는 'pets' 인상까지 줄 수 있음.
- ✗ **'15개+ 컨테이너', 'R720 보유'** 등 하드웨어/수량 자랑: 성과 아님 → "무엇을 왜 만들었나"로 치환.
- ✗ **포스트모템 자동화로 'MTTR 단축'**: 카테고리 오류 — 포스트모템은 복구 *후* 문서라 MTTR을 못 줄임. 가치는 "문서화 90분→15분".
- ✗ **'Datadog Watchdog/Dynatrace Davis로 PromQL/LogQL 생성'**: 벤더·쿼리언어 오매핑(Datadog=Bits AI+DDSQL, 자연어 PromQL은 Grafana Assistant 전용).
- ✗ **'MCP 챗옵스 봇이라 희소성 높다'**: 표준·기성 서버가 많을수록 '연결만'은 흔한 데모 → 자기모순.
- ✗ **client-go로 '간단한' 오퍼레이터**: 2026 표준은 Kubebuilder/controller-runtime, raw client-go는 '간단'하지 않음.
- ✗ **모든 bullet 강제 수치화 / 깨끗한 baseline 없는 '수 시간→수 분'**: 지어낸 수치는 "어떻게 측정했나"에 붕괴.
